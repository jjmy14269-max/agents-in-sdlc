GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat は、ユーザーのマシンでリアルタイムに実行される各ツール呼び出しやファイル編集を表示します。エディターを離れずに、チャット内で差分を確認して変更ごとに採用または取り消し、フォローアップのプロンプトで会話を調整したり作業を広げたりできます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示を追加し、ハイ コントラスト モードとともにライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じる利用者向けに、ライト モードの切り替えも追加してほしいと依頼がありました。新しい会話を最初から始めず、既存のセッションに指示を追加して作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、作業の各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに、チャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、もう一度作業するようエージェントに任せます。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したファイルの一覧を確認できます。

> [!NOTE]
> ツールの実行 (たとえば、ターミナル コマンドの実行) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。コマンドの内容を確認し、許可してもよいものだけ承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じ Chat セッションを続けるため、エージェントは以前の作業のコンテキスト、変更したコンポーネント、スタイルの方針、設定をローカル ストレージに保存する方法を引き続き利用できます。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは以前の変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラスト モードのときと同じように、新しい編集を確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好みと異なる方法でトグル UI をリファクタリングしようとした場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、説明を追加するフォローアップ メッセージを送信します。

> [!TIP]
> セッションの途中で指示を追加する方が、最初からやり直すよりも速く進められます。フォローアップ プロンプトで、調整 ("CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う")、方向の修正 ("トグルを 3 つにせず、ライト モードを既存の設定パネルに追加する")、作業範囲の拡張 ("両方のトグルにキーボード ショートカットも追加する") を依頼できます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージによる保存) が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使って、進行中のセッションを監視し、方針を調整しました。各ファイルの編集を確認して採用または取り消し、コンテキストを保ったままフォローアップ プロンプトを送信して作業を広げました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイル編集を個別に採用または取り消しました。
- フォローアップ プロンプトを使って、セッションの途中で作業の方向を調整しました。

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
